# Project Luna — решение по сборке PC

**Дата:** 2026-09-01  
**Статус:** принято для development-реализации  
**Архитектурный SoT:** `docs/ARCHITECTURE.md`

## 1. Цель

После первых интеграционных этапов Phase 2 проект должен иметь воспроизводимый x86_64 UEFI-диск, который можно записать на отдельный ПК-диск и загрузить.

## 2. Формат development image

`tools/build-pc-image.sh` создаёт:

```text
dist/luna-pc.img
```

с GPT-разметкой:

```text
EFI     128 MiB
SYSTEM  384 MiB
DATA    512 MiB
```

Development image не добавляет SWAP.

## 3. Неизменяемая система

SYSTEM содержит:

```text
images/luna-0.1.0.squashfs
images/luna-0.1.0.toml
kernels/default/bzImage
kernels/default/initramfs.img
```

`luna-0.1.0.squashfs` остаётся непосредственно SquashFS System Image. `.toml` остаётся отдельным manifest образа.

## 4. Системная libc

`luna-system-runtime` в PC image всегда строится для:

```text
x86_64-unknown-linux-musl
```

Сборщик должен остановиться, если результирующий runtime не статически связан.

Это не меняет принятую политику: glibc является compatibility runtime для приложений, а не libc системного userspace Luna.

## 5. Обнаружение устройств загрузки

Ранний userspace должен сначала пытаться найти разделы по меткам:

```text
LABEL=LUNA-SYSTEM
LABEL=LUNA-DATA
```

Старые `/dev/sda2` и `/dev/sda3` допускаются только как совместимый fallback для существующего QEMU bring-up.

Это позволяет одному development System Image работать с SATA/NVMe/USB без жёсткой привязки к одному имени block device.

## 6. UserSession и графический запуск

Development PC image должен создавать первую `UserSession` через `luna-system-runtime`.

Отдельного `/usr/bin/luna-session` не существует и создаваться не должен.

Без полного графического payload development image может оставаться диагностически пригодным через уже существующий development boot/QEMU путь, но это не должно описываться как отдельный Luna session component или как штатный TTY login.

При наличии графического payload `luna-system-runtime` передаёт управление принятой графической границе `UserSession` → Wayland → niri → Noctalia.

## 7. Безопасность установки

`tools/install-pc-image.sh` записывает только целевой целый block device и требует:

1. явного `--yes`;
2. target должен быть block device;
3. target не должен иметь mounted filesystems;
4. отдельного ввода `ERASE-LUNA` перед destructive write.

Репозиторий не выполняет запись на реальный диск автоматически.

## 8. CI

Отдельный GitHub Actions workflow должен собирать PC image на Ubuntu и публиковать artifact `luna-pc-x86_64` с SHA-256 checksum.

## 9. Область решения

Это решение относится к development build. Production installer, Secure Boot, окончательная схема manifest/compatibility, persistent boot-success state, update activation и финальный графический payload остаются отдельными задачами.
