# Project Luna — PC Development Build Decision

**Дата:** 2026-09-01  
**Статус:** принято как development implementation  
**Архитектурный SoT:** `docs/ARCHITECTURE.md`

## 1. Цель

После завершения первых Phase 2 integration passes проект должен иметь не только отдельные crates и QEMU bring-up, но и воспроизводимый x86_64 UEFI-диск, который можно записать на отдельный ПК-диск и загрузить.

## 2. Формат development image

`tools/build-pc-image.sh` создаёт:

```text
 dist/luna-pc.img
```

с GPT-разметкой:

```text
EFI     128 MiB
SYSTEM  384 MiB
DATA    512 MiB
```

Development image не добавляет SWAP.

## 3. Immutable system

SYSTEM содержит:

```text
images/luna-0.1.0.squashfs
images/luna-0.1.0.toml
kernels/default/bzImage
kernels/default/initramfs.img
```

`luna-0.1.0.squashfs` остаётся непосредственно SquashFS System Image. `.toml` остаётся отдельным image manifest.

## 4. System libc

`luna-system-runtime` в PC image всегда строится для:

```text
x86_64-unknown-linux-musl
```

и сборщик отказывается продолжать, если результирующий runtime не статически связан.

Это не изменяет ранее принятую политику: glibc является compatibility runtime для приложений, а не libc самого Luna system userspace.

## 5. Boot device discovery

Early userspace пытается монтировать:

```text
LABEL=LUNA-SYSTEM
LABEL=LUNA-DATA
```

а старые `/dev/sda2` и `/dev/sda3` оставлены только как compatibility fallback для существующего QEMU bring-up.

Это позволяет одному development System Image работать на SATA/NVMe/USB layouts без жёсткой привязки к одному имени Linux block device.

## 6. UserSession

Development PC image создаёт первую `UserSession` и запускает `/usr/bin/luna-session`.

Без графического payload `luna-session` запускает `/bin/sh`, чтобы image оставался пригодным для end-to-end development и recovery.

При наличии `/usr/bin/niri-session` и `/etc/luna/mode` со значением `graphical` system-runtime использует существующий graphical `UserSession` boundary вместо console shell path.

## 7. Installation safety

`tools/install-pc-image.sh` записывает только целый block device и требует:

1. явного `--yes` аргумента;
2. target должен быть block device;
3. target не должен иметь mounted filesystems;
4. отдельного ввода `ERASE-LUNA` перед destructive write.

Репозиторий не выполняет запись на реальный диск автоматически.

## 8. CI

Dedicated GitHub Actions workflow обязан собирать PC image на Ubuntu и публиковать artifact `luna-pc-x86_64` с SHA-256 checksum.

## 9. Scope

Это development build decision. Production installer, secure boot, final System Image manifest compatibility, boot-success persistence, update activation and final graphical payload остаются отдельными задачами.
