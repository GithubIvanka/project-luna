# Project Luna — libc и система инициализации

**Дата исходного решения:** 2026-09-03  
**Статус:** SUPERSEDED  
**Superseded by:** 2026-09-06 RAM-backed `luna-init` architecture  
**Архитектурный SoT:** `docs/ARCHITECTURE.md`

> Историческое решение о передаче управления через `switch_root` больше не является действующей архитектурой. Ниже сохранены только актуальные части libc/runtime решения и ссылка на новую модель bootstrap.

## Native Luna userspace

Нативная системная среда Luna использует **musl libc**. Это относится к `luna-init`, `luna-system-runtime` и другим компонентам native Luna userspace.

Для x86_64 PC/development image native userspace собирается через `x86_64-unknown-linux-musl` и должен быть статически связан.

## Runtime taxonomy

`glibc` не является libc системы Luna. Это compatibility runtime для отдельных приложений. Bundle-private runtime также выбирается только для конкретного application process.

```text
RuntimeKind::Luna   → native Luna userspace / musl
RuntimeKind::Glibc  → approved application compatibility runtime
RuntimeKind::Bundle → Bundle-private runtime
```

Один процесс использует один runtime kind; разные процессы могут одновременно использовать разные runtime kinds.

## Superseded initialization model

Исторически документ использовал модель:

```text
Linux kernel
    ↓
initramfs
    ↓
/init = luna-init
    ↓
mount System Image as final root
    ↓
switch_root
    ↓
/sbin/init = luna-system-runtime
```

Эта схема **заменена**.

Актуальная модель:

```text
Linux kernel
    ↓
initramfs
    ↓
/init = luna-init
    ↓
mount selected System Image as internal immutable source
    ↓
create RAM-backed logical /
    ↓
materialize boot-critical system base
    ↓
start luna-system-runtime (PID 1)
```

`luna-init` остаётся ранним bootstrap component. Он не превращает SquashFS в постоянный disk-backed `/`.

## System Image

System Image является прямым SquashFS-файлом. В новой модели `luna-init` использует его как immutable source для controlled materialization/hydration.

Initial materialization покрывает boot-critical runtime resources. Дополнительные immutable resources могут быть hydrated lazily. Materialized resources должны сохранять работоспособность независимо от lifetime исходного System Image source.

SYSTEM и DATA обнаруживаются по меткам `LUNA-SYSTEM` и `LUNA-DATA`; выбор конкретного System Image может быть задан kernel command line.

## Shell and diagnostics

BusyBox допускается в development initramfs как набор bootstrap utilities и emergency shell. Shell не является архитектурным `init` Luna.

TTY/serial не является штатным пользовательским login path и допускается только для development, diagnostics и recovery.

## Desktop startup

После bootstrap пользовательский вход остаётся графическим:

```text
luna-system-runtime
    ↓
graphical login
    ↓
UserSession::Authenticating
    ↓
authentication
    ↓
UserSession::Active
    ↓
Wayland → niri → Noctalia Shell
```
