# Контракт состояния загрузки

**Статус:** черновик для Phase 0.

## 1. Назначение

Boot State хранит только состояние, необходимое для безопасного выбора следующей загрузочной цели и обработки ошибок. Он не является общим System State и не заменяет `luna-state`.

## 2. Семантические сущности

Минимально различаются:

- `current` — текущая подтверждённая рабочая пара System Image + kernel;
- `factory` — неизменяемая заводская пара;
- предыдущие usable choices, необходимые для fallback;
- pending activation/update;
- информация о подтверждении или зафиксированном отказе.

## 3. Правило записи

Обычная успешная загрузка не должна переписывать persistent boot state без причины.

Состояние меняется только после существенных событий, например:

- подготовка новой активации;
- смена `current`;
- подтверждение новой версии;
- подтверждённый boot failure;
- rollback;
- переход в recovery/factory.

## 4. Атомарность

Изменение boot state должно быть устойчивым к потере питания в середине операции. Нельзя оставлять неоднозначное состояние, из которого невозможно понять, какая активация является безопасной.

## 5. Fallback

Boot State должен хранить достаточно информации, чтобы загрузчик мог предпочесть предыдущую совместимую рабочую комбинацию и лишь затем перейти к Factory или Recovery согласно классу отказа.

## 6. Ограничения

Bootloader не должен становиться владельцем всего постоянного состояния Luna. Долговечные системные данные находятся в `luna-state`, а UEFI-специфическая загрузочная информация должна иметь минимальный и отдельно определённый формат.

## 7. Открытые вопросы

Нужно утвердить физический формат хранения, схему версий состояния, счётчик неудачных попыток, механизм фиксации health confirmation и точные переходы state machine.
