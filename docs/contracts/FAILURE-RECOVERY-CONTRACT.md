# Контракт ошибок загрузки и восстановления

**Статус:** черновик для Phase 0.

## 1. Цель

Определить поведение Luna при ошибках System Image, kernel и раннего userspace так, чтобы отказ одной версии не приводил автоматически к потере рабочей системы.

## 2. Классы отказов

Минимально различаются:

1. ошибка обнаружения/проверки boot-артефакта;
2. ошибка запуска System Image;
3. kernel-level failure, включая panic, требующий повторной загрузки;
4. failure раннего userspace;
5. исчерпание usable fallback вариантов.

## 3. Soft fallback

Для отказа System Image, выявленного после загрузки подходящего kernel, допускается попытка предыдущего совместимого System Image без полного перезапуска, если это технически возможно и безопасно.

```text
current image
    ↓ failure
previous compatible image
    ↓ failure
next compatible fallback
    ↓
Factory / Recovery
```

Для kernel-level failure после перезапуска применяются предыдущие совместимые kernel/image комбинации согласно Boot State.

## 4. Factory

Factory — сохранённая известная рабочая пара System Image + kernel. Она не удаляется обычной retention policy и используется как последний штатный fallback перед Recovery.

## 5. Recovery

Recovery является отдельным boot mode, а не TTY fallback. Он должен оставаться доступным при повреждённом или неработающем обычном userspace и не должен зависеть от DATA больше, чем это необходимо для диагностических операций.

## 6. Автоматический rollback

Неудачная активация должна оставлять предыдущую подтверждённую комбинацию доступной. Автоматический rollback выполняется по формальным health/failure признакам, а не по произвольной догадке компонента.

## 7. Учет попыток

Необходимо различать факт попытки загрузки, факт отказа и подтверждение успешного запуска. Повторный перезапуск не должен бесконечно возвращать систему в новую неисправную комбинацию.

## 8. Открытые вопросы

Нужно утвердить точную state machine, критерии health confirmation, лимит неудачных попыток и правила перехода между fallback, Factory и Recovery.
