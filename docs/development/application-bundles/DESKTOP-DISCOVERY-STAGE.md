## Исходный пробел и реализация

Прежний установщик вручную создавал ровно две `.desktop` записи. Они не являлись
каталогом зарегистрированных приложений. Теперь существующий посредник запуска
в System Runtime получает от App Manager проверенный список с ограничением
размера, выбирает графические native musl версии с разрешениями Launch
для точного пользователя и содержимого, затем проверяет общий планировщик
установленного приложения. Временные записи XDG принадлежат root, появляются
до запуска Noctalia, обновляются явной командой `luna app list` в работающей
сессии и очищаются при выходе или ошибке обновления.

Сканер Noctalia 5.2.0 читает XDG_DATA_DIRS и следит за applications через inotify.
Его исходники проверены из уже закреплённого сборочного образа; оболочка
не пересобиралась. Каждая версия имеет служебное имя файла, а понятное имя
берётся из TOML-манифеста. Exec запускает
`/usr/bin/luna app run ID VERSION --expect-content HASH --`.
Runtime снова проверяет регистрацию, содержимое и разрешения. Устаревший хеш
отклоняется до создания хранилища приложения или проверки сокета композитора.
Меню не принимает решения о доступе. Noctalia также видит обычные записи
пользователя и системы.

Аргументы запуска по умолчанию перенесены в необязательное `entry.args`:
настройки Ghostty больше не требуют специального случая в каталоге.
Пустые аргументы не меняют прежнее каноническое представление манифеста.
Полные правила и ограничения — в
[контракте запуска](../../contracts/APPLICATION-LAUNCH-CONTRACT.md).
Новый фоновый сервис, управление установкой через IPC и расширенный доступ
терминала к сокету запуска не добавлены. Собственные значки бандлов,
«Показать содержимое» и полная экосистема сторонних приложений ещё не реализованы.

Mod+Space открывает меню запуска; Mod+Return и Mod+E остаются быстрыми
сочетаниями клавиш. Начальная публикация и обновление проверяют весь ограниченный
снимок реестра. Постоянного наблюдения за реестром и API установки/обновления/
удаления из работающей сессии пока нет.
