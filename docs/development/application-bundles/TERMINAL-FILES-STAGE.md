# Ghostty/fish и графический Luna Files

Ветка `luna-onefile-experiment`, HEAD `a1ea279`; существующие изменения
и пользовательские сценарии проверки сохранены, без коммитов и сброса изменений.
Полный канонический прогон QEMU этого этапа принят 2026-10-12:
новый эталон A, предыдущий принятый B сохранён.
Более новые результаты описаны в [этапе каталога](DESKTOP-DISCOVERY-STAGE.md)
и [этапе файловых операций](FILES-OPERATIONS-STAGE.md).

## Проверенная исходная проблема

В исходном снимке поставщиков ресурсов отсутствовали Ghostty, fish, Bash, Yazi
и Luna Files, хотя desktop.toml уже называл Ghostty. Старые сборщики использовали
glibc. GTK-прототип Luna Files напрямую вызывал std::fs; у существующего
FileBackend реализации не было. Прежнее обещание готового независимого движка
Yazi было неточным: исходный проект даёт переиспользуемые файловые операции,
но не готовый сервер для GUI.

## Реализация

Luna Files остаётся существующим внешним компонентом-поставщиком ресурсов:
самостоятельный GTK-интерфейс использует `yazi-fs::engine::local::Local`,
закреплённую ревизию Git `8dd895c695a5950330c2623eb43debf323b60654` (v26.9.1).
Эта версия библиотеки не опубликована в crates.io, поэтому точная ревизия
закреплена и в Cargo.lock. Терминальные Yazi/ya собираются из того же коммита.
Глобальное состояние терминального интерфейса и полный Scheduler в GUI
не запускаются.

GUI поддерживает асинхронное чтение, размеры и ссылки, сортировку папок перед
файлами, навигацию в одном окне, Home/Up/Refresh, адресную строку (Ctrl+L),
создание папки (Ctrl+Shift+N), настоящие ошибки и --reveal с выделением строки.
Один рабочий поток с Tokio обрабатывает ограниченные запросы; GTK остаётся
в главном цикле. Старые ответы не отменяют новые переходы. Слабые ссылки
на виджеты исключают циклы владения обработчиками сигналов; неизменённая
адресная строка сохраняет исходные байты пути, даже если они не являются UTF-8.

Создание папки использует Yazi create_dir, проверяет одно имя и не заменяет
существующий объект. На момент этого этапа копирование, перенос, переименование,
удаление, рекурсивные операции, отмена и открытие другим приложением отсутствовали.
В исходном Yazi копирование обрезает назначение, а переименование может его
перезаписать: безопасная политика нужна до включения кнопок. Каталог ограничен
10000 записями с явной ошибкой при превышении. Это начальный рабочий графический
набор возможностей, а не полное совпадение с терминальным Yazi.

Ghostty v1.3.1 закреплён коммитом `332b2aefc6e72d363aa93ab6ecfc86eeeeb5ed28`
и явной поправкой Luna `tools/alpine-foundation/ghostty-wayland-app-id.patch`:
при инициализации Wayland имя программы GLib задаётся по выбранному классу
приложения. Без сессионного D-Bus исходный Ghostty игнорирует этот запасной путь,
и настоящее окно называлось `GTK Application`. Поправка подключается только
для чтения внутри контейнера SDK; рабочая копия хоста остаётся без изменений.
`class = org.luna.terminal` согласует идентификатор окна с записью об установке
и записью меню. Files тоже задаёт `org.luna.files` до инициализации GTK
и передаёт argv0; первоначально его окно имело `<unknown>`.

Zig 0.15.2 проверен по официальной SHA256. Его зависимости сверены
с закреплёнными хешами пакетов; подписи Alpine APK проверены apk.
Оболочка — Alpine native musl fish 4.6.0. Bash 5.3.9 и BusyBox sh находятся
в бандле Terminal. Системный `/bin/sh` остаётся POSIX BusyBox ash;
fish не становится интерпретатором системных скриптов.

Terminal и Luna Files доставляются как `.lbp`, затем AppManager устанавливает
их как directory-v1 `.lunaapp` с TOML-манифестом/описанием целостности
и обычными файлами полезной нагрузки, без вложенного архива. Библиотеки
выбираются только из закреплённого Alpine SDK и канонических входных ресурсов
Mesa; все необходимые зависимости получают разрешения на точные файлы.
Дополнительные ресурсы и библиотеки для dlopen выбраны явно; зависимости
от glibc хоста нет. RPATH/RUNPATH удаляются из копии с записью хешей до/после.
Нормальный образ содержит зарегистрированные приложения и принадлежащую root
политику Launch. Записи меню и Mod+Return/Mod+E вызывают существующий
`luna app run`. На этом этапе это был фиксированный начальный набор Alpha;
общий проверяемый менеджером каталог реализован в следующем этапе.

Первый настоящий запуск Files обнаружил SIGSEGV до появления окна:
журнал ядра указал `libxkbcommon.so.0+0x1efb7` (`xkb_keymap_ref` с null keymap).
В бандле не хватало данных XKB: GTK 4.22.4 создаёт начальную карту клавиатуры
через xkb_keymap_new_from_names до получения карты от композитора
([исходник GTK](https://raw.githubusercontent.com/GNOME/gtk/4.22.4/gdk/wayland/gdkkeymap-wayland.c)).
Добавлены явные ресурсы XKB/Compose и два логических пути для одних обычных
файлов: `/usr/share/X11/xkb` и `/usr/share/xkeyboard-config-2`.
Второй путь Alpine предоставляет как псевдоним. Каталоги хоста не добавляются.

Разрешения `user.home`/`terminal.pty` описаны в
[контракте запуска](../../contracts/APPLICATION-LAUNCH-CONTRACT.md).
PTY (псевдотерминал) принадлежит приватному devpts, fish — тому же
ApplicationInstance и cgroup, группе учёта процессов. Доступ к аппаратному
GPU, порталам и аудио не выдан; Ghostty использует программный llvmpipe.
Внешние тома, glibc, полный планировщик Yazi и экосистема сторонних приложений
остаются дальнейшими этапами.

## Сборка и подтверждения

`tools/alpine-foundation/desktop-apps.Dockerfile` описывает SDK.
`tools/build-luna-desktop-apps-musl.sh` требует явно закреплённый образ SDK
и точные ревизии исходников, работает без сети и не сбрасывает рабочие копии.
Запись о сборке связывает ID образа SDK, базу пакетов, ревизии исходников,
SHA256 поправок/накладок и четырёх собственных двоичных файлов.
Упаковщик проверяет запись и отклоняет устаревший файл, изменённую поправку
или другой SDK. Проверка ContentIdentity остаётся отдельной границей runtime.
`tools/prepare-luna-desktop-bundles.py` формирует настоящие данные бандла,
сведения о происхождении и транспортный пакет;
`tools/install-luna-desktop-bundles.py` устанавливает начальный набор через
App Manager. Канонический сборщик берёт необязательные desktop-bundles только
из проверенного входного снимка.

После успешной упаковки промежуточные исходные данные удаляются автоматически;
сохраняются `.lbp`, исходные TOML-манифесты, политика, JSON происхождения
и запись о сборке. `--keep-payload` нужен только для диагностики.
Повторная упаковка дала те же хеши архивов и ContentIdentity и подтвердила
очистку. Старые диагностические копии этого этапа удаляются после принятия QEMU;
кэши компиляции и два управляемых образа переиспользуются.

Закреплённый SDK: `luna-terminal-files-sdk:20261011-offline`, ID образа
`sha256:ea159c09a0baab1b0002ac34dd5f0ed2f1dd55a87dd68bce5058cb881acff0b4`.
Транспортные пакеты/манифесты/происхождение этого этапа:
`target/luna-terminal-files-20261011/bundles-gui-terminal/`;
входной снимок: `target/luna-terminal-files-20261011/inputs-gui-terminal/`.
Повторный канонический прогон:

```bash
CARGO_HOME="$PWD/target/luna-terminal-files-20261011/cargo-home" \
LUNA_QEMU_DISPLAY=egl-headless \
LUNA_CANONICAL_WAYLAND_FIXTURE="$PWD/target/luna-terminal-files-20261011/wayland-fixture-gui-terminal" \
python3 tools/canonical-luna-workbench.py run build \
  --inputs target/luna-terminal-files-20261011/inputs-gui-terminal
```

Реальные данные приложений не помещались в фиксированную DATA 1GiB:
mkfs.btrfs --rootdir увеличивал файл, но GPT сохраняла прежние границы.
Сборщик теперь измеряет содержимое DATA, добавляет 50% и 256MiB, округляет
до 256MiB и проверяет точный размер файловой системы перед переносом в раздел.
Очистка делает каталоги неизменяемых пакетов доступными для записи только
через закреплённый дескриптор каталога внутри помеченного дерева сборки.
Статические и конкурентно подменённые ссылки не меняют права внешних целей;
при сбое эталонный слот сохраняется.

Журналы: `target/luna-terminal-files-20261011/evidence/`. Перед изменениями
сохранены 354 исходных пути и двоичная разница файлов. Проверки движка:
8 тестов хоста и 8 статического musl; адреса GUI — 2 теста.
Проверка GTK на хосте, сборка musl GUI и Clippy Files в области изменений прошли.
В SDK нет Clippy, поэтому Files проверен на хосте;
AppRuntime/SystemRuntime/CLI — на native musl. Пространства имён/безопасность:
31 тест; упаковка/записи/очистка после ошибки: 12;
жизненный цикл артефактов: 28 PASS. Канонический набор также проверил
25 тестов состояния/runtime, 104 теста app-runtime (один привилегированный
пропущен, настоящая настройка процесса проверена QEMU), 4 теста init
и 6 проверок отказов для входных данных. Независимый просмотр завершён.

Полный канонический прогон по исходникам этого этапа — **PASS**:
`target/canonical-workbench/evidence/20261012-073541-834991/results.txt`.
Структура/владельцы, загрузка/видеопереход, три сессии рабочего стола,
выход/повторный вход, перезагрузка/выключение гостя и 16 прежних отметок
проверки бандлов проходят. `bundle-launch/desktop-results.txt` подтверждает:

- Niri JSON содержит точные app_id `org.luna.files` / `org.luna.terminal` и PID.
- Виртуальная клавиатура в Files переходит в `/home`, создаёт `gui-test`
  и закрывает окно с кодом выхода 0; операция использует настоящий движок Yazi Local.
- В Ghostty настоящий fish принимает ввод; Bash и POSIX sh выполняют команды.
  Терминальный Yazi запускается и после `q` возвращает управление fish с кодом 0.
- UID 1000; потомки терминала имеют одно пространство монтирования и cgroup.
  fd 0 fish/Yazi совпадает по устройству/номеру объекта с приватным devpts;
  консоль или dri хоста не доступны.
- Выход уничтожает потомков терминала/fish. Созданные файлы HOME и каталог
  сохраняются; реестр, данные и настройки проверены после перезагрузки гостя.
