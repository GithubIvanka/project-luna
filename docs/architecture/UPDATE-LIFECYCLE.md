# Жизненный цикл обновления

## Владение

`luna-update-manager` координирует транзакции обновления. `luna-system-manager` владеет идентичностью системных target. `luna-state` предоставляет долговременное транзакционное хранение. Изменение конкретных артефактов выполняется явно определёнными backend-реализациями обновления.

## Обновление System Image

```text
кандидат System Image
  ↓
проверка image + manifest + совместимого init/core
  ↓
подготовка
  ↓
checkpoint / долговременная фиксация подготовки
  ↓
атомарная фиксация target state
  ↓
выбор при следующей загрузке
  ↓
подтверждение семантического успеха
```

System Image, `luna-init` и kernel остаются независимо версионируемыми артефактами, но boot target всегда должен быть совместимой тройкой `System Image + luna-init + kernel`.

## Откат

Откат изменяет идентичность полного target `System Image + luna-init + kernel`, а не смешивает артефакты независимо друг от друга.

## Прерванное обновление

Долговременное состояние хранит достаточно сведений о транзакции и revision, чтобы обнаружить прерванную операцию. До фиксации нового конфликтующего обновления reconciliation должна либо завершить транзакцию, либо безопасно отказаться от неё.

## Подтверждение загрузки

Новый target не считается подтверждённым только потому, что файлы были записаны. Семантический запуск runtime должен достичь границы успеха, после которой очищается `LunaBootAttempt` и через владеющий manager обновляется долговременное состояние текущего target.
